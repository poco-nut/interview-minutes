# 写作规范

## 一、引导短语（新旧写法最显著的分水岭，强制）

**每节内每个段落**以加粗的 3–8 字标签 + 全角冒号开头，后接正文，同一段内不换行。

2025 年的老版式（云帆信科）是纯段落流水，从 2026-08 起的新版式四份样本全部改成了引导短语结构。**这是必须遵守的第一条。**

标签取自样本的实际用法：

| 场景 | 可用标签 |
|---|---|
| 公司基本情况 | `成立情况` `公司命名与技术原理` `技术渊源` `后续架构安排` `定位与产品形态` |
| 融资 | `天使轮融资` `本轮融资安排` `融资历程` `资金用途` `财务预测` |
| 团队 | `人才结构特点` `代际传承` `招聘方向一` `研究团队` |
| 技术 | `技术简介` `使用场景` `技术竞争优势` `研发进展` `量产时间线` `底层驱动` |
| 市场 | `WAT 市场测算` `OWT 市场测算` `市场空间` |
| 竞品 | `竞争格局分析` `差异化壁垒` `现有 WAT 格局` |

要求：
- 标签是**名词短语**，不是句子
- 同一节内的标签不重复
- 一节里最多 1 段不带标签（用于承接过渡）；带标签的段落应占多数

**例外：创始团队节** —— 段首标签写 `姓名（职务）`（`李明（创始人、CEO/CTO）`），**一人一段**。姓名不是名词短语，但这是样本的固定用法（云驰半导体的 `陈总（创始人、CEO/CTO）`）；因姓名各不相同，也不违反「同节标签不重复」。顾问与管理层同样逐人成段，**不要把几人的履历合并成一段无主语清单**。

## 二、禁止归属短语（强制）

**观点、判断、预测、结论一律写成直接陈述句**，不带主语。全文禁止出现指名归属短语：

`创始人认为` `创始人介绍` `创始人确认` `创始人强调` `陈总表示` `李总补充` `据 X 介绍` `X 了解` `X 判断` `X 确认`

```
✗  陈总认为，晶圆级硅光测试的难度比 WAT 高很多，最终留下的玩家会与国际市场一样只有两三家。
✓  晶圆级硅光测试的难度显著高于 WAT，最终留下的玩家会与国际市场一样只有两三家。

✗  陈总确认，晶圆级测试在可插拔时代不做，只做模组级或带级。
✓  晶圆级测试在可插拔时代不做，只做模组级或带级。
```

**唯一例外**：轻度核查的括注可用不带人名的中性来源词（`公司口径` `据公司自述` `受访人表述`），见第十节。

多人口径的区分不靠归属短语，靠**正文／Q&A 分流机制**承担——主动陈述进正文节，提问引出进 Q&A，见 `qa-spec.md` 第一节。

## 三、人名规范

姓名现在只出现在**元信息块**与**创始团队节**（后者通常来自 BP）——正文与 Q&A 答案里不再用姓名做归属（见第二节）。

- 首次出现：`姓名（职务、职务）` —— `张伟明（创始人、CEO）`、`陈总（创始人、CEO/CTO）`
- 只给了姓氏（`陈总`）时照写 `陈总`，**不要推断全名**
- 学术头衔随名列出：`欧阳明院士（控股股东）`、`陈立群（首席科学家）`
- **不要**用姓氏反推全名，也不要为了行文顺畅把 BP 上的英文名译成中文名

创始团队节内 **一人一段**：`姓名（职务）` 作段首加粗标签，段内只写这一个人的学历、履历与成果，各人之间不合并、不交叉。BP 以卡片形式逐人列团队时（姓名 + 职务 + 履历三件套），照此结构搬运即可，**不要压缩成一段并列清单**——那样读者看不出哪条履历属于谁。

## 四、机构名规范

- 首次出现用全称 + `（以下简称"X"）`，其后一律用简称
- 简称在「项目简介」段里定义一次即可，正文直接用
- 外文机构保留原文：`Keysight`、`Tower`、`GlobalFoundries`；首次可加中文：`是德科技（Keysight）`

## 五、数字与单位

- 单位：`亿元` `万元` `万` `千万`；不写 `RMB` `¥`
- 规模前加缓冲词：`约` `超过` `量级` `以上` `左右` —— 样本几乎每个数字都带一个
- 区间用 `至` 或 `-`：`400 万至 500 万元/台`、`2,000 万—3,000 万元`
- 千分位：四位数以上加逗号（`3,000 万元`）
- **口径必须跟着数字**：`（公司口径）` `（按 12 寸晶圆厂产能口径）` `公司测算`
- 受访人自述与公开数据不一致时**并列**，不取其一

## 六、原话引用

关键定位、定价逻辑、技术主张加引号原样保留，**不改写**：

> 业务边界为「我们只会做 test 和纯对准那一块」，对准加 probe 与双面测试的 probe 坚决不做。

引用要短（一句以内），其余转成间接引述。**引号前后不写归属短语**（见第二节）。

## 七、分点

多要点用汉字序号，**不用 markdown 列表**（docx 里列表符号会和公司版式打架）：

- 三项以上：`一是……二是……三是……`
- 三项以上且每项较长：`其一……其二……其三……`
- 并列短标签：`①……②……③……`（卓然用过）

## 八、敏感信息与拒答

如实记录，**不美化、不省略、不编造理由**：

> 关于江苏张某：该问题未获正面回应，受访方愿意线下再沟通；并说明公司在法律上切割得很干净，不会有任何问题。

> 真正从九院出来的是否只有刘峰一人，据受访方自述（不一定准确）。

拿不准的一律括注 `（不一定准确）` `（未进一步说明）`。**拒答本身就是尽调信息，不要替受访人圆场。**

## 九、清洗规则（针对语音转写稿与现场手记）

### 转写稿

1. **去口语化**：删 `呃` `那个` `我是说` `就是说` `对吧`、语气词、重复词、结巴
2. **同音错别字按行业正写法纠正**：`Z箍缩`（非 Z 估缩）、`硅光`（非 归光）、`焦平面`（非 交点面）、`允收测试`（非 允许测试）、`氘氚`（非 刀穿）—— 拿不准的技术名词宁可标 `（待核）` 也不要猜
3. **合并同类项**：同一话题在转写稿里被反复提及，合并到同一节/同一 Q
4. **拆分长句**：转写稿一句话常带三四个分句，拆成 2–3 句

### 现场手记

5. **补全主谓**：手记只有关键词（如「中芯 demo 9 月上台机」），补成完整句
6. **还原逻辑链**：手记里的箭头、缩进要还原成因果或并列关系，还原不了就标 `（待补）`

### 两条硬约束

7. **禁止编造**：素材里没有的**数字、人名、职务、机构**一律不补。缺的写 `（待补）`，不写「约」「大约」蒙混
8. **来源冲突**：转写稿与手记打架时，以**转写稿原话**为准；无法判断就并列标注

## 十、轻度核查

对以下内容做 WebSearch 快速复核：市场规模、融资额、估值、专利/论文数量、公开头衔（院士／杰青／优青／型号总师）。

**只标注，不改写**：

> 核心团队拥有专利 100 余项（公开检索到的该公司专利公开量为 30 余项，此处以公司口径为准）

核查结果在第 6 步输出成表，三列：`原始表述` / `公开口径` / `是否存疑`。

核查不通过也**不删原话、不改原话**——纪要记录的是对方说了什么，不是对方说得对不对。
